## Projection And Size Safety

Facts <=200; signals <=100; recommendations <=10; pending decisions/approvals <=100; graph nodes <=500 and edges <=1000 with endpoint visibility; briefing lists <=100 each; decision details <=100; memory results <=100 with <=50 recent history entries each. The limitation now also reports graph-edge and decision truncation, which were previously omitted from its trigger. Node insertion and final edge filtering use sets, preserving order and endpoint semantics while removing quadratic lookups in those hot paths.

Memory serialization is measured incrementally; combined memory above 1MiB fails explicitly. Final serialized SIA response above 1MiB also fails explicitly with the existing safe capacity error. No oversized response is reported as a successful partial answer. This is a DTO byte budget, **not** an exact heap bound, SQL query cap, token cap or enterprise capacity guarantee. Large single stored payloads and pre-projection authorized source/include fan-out can still incur materialization cost before the final guard.

Request-local history reuse is data reuse, not permission reuse. Every decision reference still reloads its canonical header and validates exact scope/capability. No source survives a changed scope just because earlier memory referred to it. Existing final human/agent/tool checks remain. Reads across services are not claimed to be one atomic dashboard snapshot.

## Remaining Acceptance Findings

Broad contexts still recompute many source/access checks; hierarchy/principal include bounds and combined child fan-out remain cost risks. A very large unrelated **task** company is excluded before task load, as tested; this does not prove unrelated organization/reference/visible-person membership volume has no effect. No blanket claim that all queries are bounded or all unrelated companies are cost-neutral is made. Address materialization/authority-query scaling only through an approved scoped follow-up after independent review; no permission shortcut introduced here.
