# Nice Jobs application to offer: Phase 3

The two launch job codes (`JOB-001` Academic Advisor and `JOB-DCM` Defence Career Mentor) use a guided application only when their published job version requires and configures pre-offer orientation. The existing versioned job registry and candidate-owned application record remain the source of truth. Earlier application records retain their existing status and history.

For a configured launch job, `DRAFT` takes short answers. `START` records an `ORIENTATION_INVITED` application and an in-app invitation. That status is **not** a hiring decision or offer. The candidate completes the versioned video comprehension and policy acknowledgement before `COMPLETE_DETAILS` submits all required answers for human review. The server rejects a direct `SUBMIT`, premature `COMPLETE_DETAILS`, duplicate `START`, stale revision, and management decisions before `SUBMITTED`. The application number is assigned on invitation; `submittedAt` records detailed submission. All mutations retain the application history and operational event.

The existing independent management approval, named offer preparation and issuance, versioned snapshot, candidate acceptance, training enrollment and separate readiness-backed worker activation remain in force. There is no standing-offer rule, so there is no instant-offer route. An accepted offer does not activate work. The private Work ID view derives its fields from the current authorized active assignment and appears only after activation; it is not a government identity document.

An issued offer is available in-app for the candidate to review and download. Offer email delivery has **not** been implemented or verified: the current share control creates an unsent `.eml` draft, and the Resend OTP sender is for authentication. No UI or audit record may claim an offer email was delivered. Before enabling offer email, define an approved transactional template and sender, verify the recipient address and messaging authority, use the existing consent-aware communications service, and record actual dispatch and failure results without changing offer issuance history.

The job catalogue remains unpublished until employer identity, terms, compensation, manager authority, orientation and programme requirements pass their existing approval gates. Local unit/UI checks do not substitute for the dedicated PostgreSQL journey test or a real candidate pilot.
