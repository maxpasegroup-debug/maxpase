# Nice Jobs Phase 5: TARA and manager operations

TARA uses the existing authorized, read-only SIA tools. The Nice Jobs name is a product persona; the audited SIA identity remains the actual agent. In the current deterministic provider mode, applicant guidance supports the four displayed application questions, and worker guidance supports the displayed work questions. Other free-text requests fail explicitly. This is not a general-purpose conversational model.

Successful applicant and worker turns are stored on `SiaRun` with a prompt, structured response, and a context key tied to the candidate-owned application or current active worker assignment. Worker history retains only general guidance; live task, lead, performance and financial details are omitted because access may later be revoked. The existing unique idempotency key, agent identity, actor, scope, tool, status and audit record remain authoritative. Failed runs do not enter the visible transcript. Transcript reads recheck the current user's owned application or active assignment and return at most 20 recent turns. Other SIA activity is unaffected. The new fields are nullable so historical runs remain valid. Prompts and results are not placed in audit metadata.

The manager queue combines existing, permission-scoped sources: submitted applications, ready offers that the viewer may issue, evidence assigned to the viewer for review, overdue tasks, and open worker blockers. Each group is bounded to five records and links to its existing detail and human-decision workflow. A queue link is never approval or execution authority. Empty and unauthorized groups have different labels. The source workflows still enforce independent offer, activation, employment, disciplinary and financial decisions.

The additive `20261104000000_nicejobs_tara_transcript` migration must be reviewed and applied to an authorized PostgreSQL target before this code is deployed. No production migration or real candidate interaction was performed in this development step. Database-backed isolation, replay and rollback checks remain required against a dedicated test target.
