# Phase 7 — Brand reporting and command centres

The Boss brand centre now opens operating modules only when their existing workspace and current permission allow it. The report reuses the Brand, Product, Project, Program, Task and ExecutiveRecord sources. It creates no reporting table, shadow CRM or inferred brand ownership. Startup Skool admissions, marketing campaigns and commercial proposals use the existing verified division and brand-keyed source references. The commercial figure describes proposals and does not authorize an invoice or payment.

The Boss report counts **shown** projects, products, programmes and overdue tasks from bounded reads. Admissions, campaigns and commercial proposals use exact scoped status aggregates, but the displayed figure is capped at the source workspace's current 100-record view. When a source exceeds its visible limit, the page says more records exist. Each shown number opens its source workspace; admissions and campaigns support status filtering. Freshness is based on the most recent recorded update in each connected source, with a seven-day label; it is not an overall brand-health score. Zero means a connected authorized source has no matching records. Null means unavailable, unauthorized or unconnected, and is never displayed as zero.

The Skill City director desk keeps its exact division counts. Each authorized count opens a paginated, read-only source list through the Skill City gateway. The report revalidates the director workspace and exact division permission on each request. It shows the source record status, last update and a next-page link. A company or division membership is not automatically assigned to a brand.

Current coverage limits: shared CRM records do not consistently carry a canonical brand relation, so a Boss brand-sales total is unavailable. Company people counts do not establish brand staffing. Financial documents and payment state require verified issuer, approved terms and source-specific controls; this report does not claim financial completion. Unavailable modules remain unlinked. No customer, student or employee portal access is granted by a report link. Browser, live-data and production verification remain separate release checks.
