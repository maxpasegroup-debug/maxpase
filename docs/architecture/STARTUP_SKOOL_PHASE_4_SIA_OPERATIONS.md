# Startup Skool Phase 4 — bounded SIA guidance and operations

The Startup Skool portal now projects deterministic, read-only guidance from authorized applicant, founder and programme-team views. The guidance is **not a model response** and does not call a production AI provider. It uses status, counts and approved milestone progression; it excludes free-text application answers, evidence and community posts from the guidance input. Each projection exposes its source, bounded coverage and limitation. Unknown access or missing records remain unavailable rather than being inferred.

Applicant guidance uses the signed-in person's own application. Founder guidance uses only currently authorized `BatchParticipant`/approved-plan data and distinguishes accepted, submitted and rework evidence. Staff guidance uses current `program.manage` access to the Startup division and the first 50 applications, first 50 evidence submissions and first 30 programme batches. These are **window counts**, not all-time totals. The separate admissions review page summarizes only its visible application window.

Human authority remains in the existing server actions: application decisions, independent batch-plan approval and mentor evidence review require current permission and are recorded with true human actor, history and operational event in a transaction. The SIA display cannot call these actions, impersonate a reviewer, change programme terms, enroll a founder or execute a tool. Recent human decisions shown on the staff desk are read from `ExecutiveHistory` in the same division scope. Revocation is checked again when the page is read or a mutation is submitted.

This is portal-local presentation guidance, not a newly registered SIA tool or an agent grant. The shared `SIA_PROVIDER=deterministic` development router and its execution controls are unchanged. A production model requires an approved provider, scoped human/agent tool intersection, privacy and prompt-injection safeguards, evaluation, observability, operating costs and human sign-off. The Phase 1 legal, commercial and admissions approvals and Phase 2/3 isolated PostgreSQL and live-provider verification remain open. Nothing here activates autonomous admissions, mentoring decisions, payments or outbound messages.
