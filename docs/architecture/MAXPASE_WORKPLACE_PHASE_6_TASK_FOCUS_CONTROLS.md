# Phase 6: Task and focus controls

This phase extends the existing Skill City Manager and Labs Developer desks over canonical `Task`, `Project`, `ExecutionBlocker` and `Responsibility` records. It adds no table, role template or autonomous authority. All actions use the signed-in actor; client-supplied actor or organization claims are not accepted.

An authorized manager of a current direct report can change an open assigned task's non-terminal status and deadline. Deadline controls explicitly distinguish keep, set and clear. The command requires `task.read` and `task.manage` in the task's actual scope, checks the task revision, preserves ownership and assignment, and records the reason and before/after values in the operational audit. The canonical Task service rejects a move out of `BLOCKED` while an open task blocker remains. It continues to enforce project closure, prerequisites, date constraints and completion rules.

Opening or resolving a task blocker requires `blocker.manage` in the same scope and a current direct-report relationship. The canonical blocker service performs resource checks and mutation; the manager wrapper and operational audit share its transaction. A blocker does not silently change task status. Repeated command references return the original result; conflicting replays fail. The current director templates do not grant `blocker.manage` automatically.

An authorized manager can end an active approved focus early with a reason. The `Responsibility` becomes archived, remains in focus history, and grants no access. The direct-report relationship and `responsibility.read`, `responsibility.manage`, and `decision.decide` are rechecked at mutation time. An ended focus cannot be silently reinstated.

For Labs developer work, an assignment marks the canonical Task metadata as review-required. A manager can complete it only after a separately assigned code reviewer and tester have each recorded a current `APPROVED` result. The reviewers cannot be the task assignee. Reviews must follow the latest task update and contribution; the latest result for each duty controls the decision. The manager must be independent of the assignee and hold scoped `task.manage`, `responsibility.read` and `decision.decide`. Canonical Task completion independently enforces review evidence, `decision.decide`, actor independence, open blockers, prerequisites and required worker evidence for every caller; the review-required marker cannot be removed through canonical updates. Completion is not project acceptance, release, deployment, employment or financial approval. The director role template lacks `responsibility.read` and `responsibility.manage` by default; reviewed completion and duty assignment remain unavailable until authorized grants are approved.

Task, blocker, focus and reviewed-completion mutations are transactionally audited. Tests use an isolated disposable database for replay, stale revision, self-review, revoked access and audit rollback. Real account appointments, role grants, project scope and deployment remain owner-controlled and were not changed in this phase.
